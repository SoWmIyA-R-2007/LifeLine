🔒 Privacy & Security Architecture

  • Zero Data Selling: LifeLine does not profile, monetize, or train AI models on your personal memories or photos.
  • PostgreSQL Row Level Security (RLS): When connected to Supabase, database records are protected by cryptographic JWT tokens ensuring only you can read or edit your records.
  • Private Cloud Storage: High-resolution photos are stored in dedicated cloud buckets with secure authenticated access.
  • Client-Side Optimization: Images are compressed right in your browser via HTML5 Canvas before leaving your machine.

Frequently Asked Questions

How does Demo Sandbox mode work?

If you haven't connected a Supabase database yet, LifeLine stores your memories locally in your browser's persistent storage. You can test photo compression, year scrubbing, and editing without any cloud setup.

Can I upload multiple photos per memory?

Yes! Drag and drop or select multiple files simultaneously. Each image is compressed to WebP/JPEG with high efficiency, and you can browse them via the carousel in detail view.

Supabase SQL Schema Migration

Run this script once in your Supabase SQL Editor:

-- 1. Create memories table with multi-photo support
CREATE TABLE IF NOT EXISTS public.memories (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  title TEXT NOT NULL,
  description TEXT,
  date DATE NOT NULL,
  category TEXT DEFAULT 'Personal',
  location TEXT,
  importance INT DEFAULT 3 CHECK (importance BETWEEN 1 AND 5),
  is_milestone BOOLEAN DEFAULT false,
  is_favorite BOOLEAN DEFAULT false,
  privacy TEXT DEFAULT 'private',
  media_url TEXT,
  media_path TEXT,
  photos JSONB DEFAULT '[]'::jsonb,
  tags TEXT[] DEFAULT ARRAY[]::TEXT[],
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Performance indexes
CREATE INDEX IF NOT EXISTS idx_memories_user_date ON public.memories (user_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_memories_category ON public.memories (user_id, category);
CREATE INDEX IF NOT EXISTS idx_memories_milestones ON public.memories (user_id, is_milestone);
CREATE INDEX IF NOT EXISTS idx_memories_favorites ON public.memories (user_id, is_favorite);

-- 3. Row Level Security (RLS)
ALTER TABLE public.memories ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can manage their own memories"
  ON public.memories
  FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

-- 4. Storage bucket setup
INSERT INTO storage.buckets (id, name, public)
VALUES ('lifeline-media', 'lifeline-media', false)
ON CONFLICT (id) DO NOTHING;

CREATE POLICY "Users upload their own memory media"
  ON storage.objects FOR INSERT
  WITH CHECK (bucket_id = 'lifeline-media' AND auth.uid()::text = (storage.foldername(name))[1]);

CREATE POLICY "Users view their own memory media"
  ON storage.objects FOR SELECT
  USING (bucket_id = 'lifeline-media' AND auth.uid()::text = (storage.foldername(name))[1]);
